## 1. Исходные данные и ограничения

В качестве отправной точки взят исходный репозиторий `aidd-topic-03-homework`
(Django 4.2, PostgreSQL, Celery + Redis, Tinkoff Invest API). Проект в исходном
виде на моей машине **не запускался**: `tinkoff`, `tinkoff-investments` и
`grpcio` не имеют сборок под Python 3.14, Docker недоступен, PostgreSQL и Redis
поднять нечем.

Поэтому каждому агенту с самого начала были заданы жёсткие рамки:

> Python 3.14. Пакеты `tinkoff`, `tinkoff-investments`, `grpcio`, `celery` не
> работают — их нужно убрать. Docker нет, PostgreSQL нет — переведи проект на
> SQLite. Проект обязан запускаться и открываться в браузере, графики должны
> строиться без токена.

Работа велась в двух независимых копиях проекта (как требует задание): агенты не
видели результатов друг друга. Итог сохранён в папках `agent_a_claude/` и
`agent_b_copilot/` — каждая является полным проектом и может быть закоммичена в
отдельную ветку (`agent-a-claude`, `agent-b-copilot`).

### 5.1. Как шла работа

| --- | --- | --- |

Код Copilot сгенерировал практически моментально, но «готовым к запуску» он не
был: суммарно на доведение ушло около **1,5 часов** (2 итерации, ≈6 запросов, из
них 4 — точечные правки после найденных ошибок) — больше, чем на саму генерацию.

### 5.2. Конкретные ошибки

1. **Миграции.** Copilot создал модели, но не создал миграцию. `migrate`
   отработал «успешно», а первая же страница портфеля упала:

   ```
   django.db.utils.OperationalError: no such table: dashboard_portfolio
   ```

   После `makemigrations` всплыла вторая ошибка: в сгенерированной миграции не
   было `migrations.swappable_dependency(settings.AUTH_USER_MODEL)` для FK на
   пользователя, и `migrate` падал с `NodeNotFoundError`. Пришлось пересоздавать
   `0008` вручную и проверять зависимости.

2. **Логика продажи.** В `Transaction.save()` ветка `SELL` не уменьшала
   количество:

   ```python
   elif self.transaction_type == "SELL":
       # Сгенерировано Copilot: продажа меняла только среднюю цену,
       # количество акций в позиции оставалось прежним.
       # TODO: Исправлено вручную после ревью: логика продажи не уменьшала количество
       # asset.quantity = asset.quantity
       asset.quantity -= self.quantity
   ```

   Баг виден в коде как закомментированная ошибочная строка с пометкой о ручной
   правке. Именно на нём сломался мой первый прогон: купил 10, продал 4 —
   в портфеле осталось 10.

3. **Дублирование.** Пересчёт `units + nano / 1e9` продублирован в `tasks.py`,
   `views.py` и `graph.py` — «в лоб», без `utils.py`. Работает, но при изменении
   формулы править нужно три места.

4. **Поиск в API.** `search_fields = ["$name"]` (синтаксис PostgreSQL) на SQLite
   давал `NotSupportedError` при `?search=`.

5. **Пагинация без сортировки.** `Paginator(Share.objects.all(), 20)` выдавал
   `UnorderedObjectListWarning` — добавил `order_by("id")`.

### 5.3. Что в итоге работает

SQLite, удалённые Tinkoff/Celery, mock-котировки, CRUD акций, график, портфель с
покупкой/продажей, 404 через `try/except Share.DoesNotExist`, 13 тестов. При этом
цена осталась во `FloatField`, модель не проверяет продажу сверх остатка (только
view), история операций не удаляется.

* Работает в чате/IDE и **не имеет доступа к терминалу**: `makemigrations`,
  `migrate`, `runserver` и тесты запускал я сам и возвращал агенту вывод ошибок.
* Контекст ограничен: пришлось дробить задачу на 4 итерации и заново прикладывать
  фрагменты `settings.py`/`models.py`.
* Отвечает заметно медленнее Copilot (десятки секунд — минуты на итерацию),
  на длинных файлах склонен пересказывать код вместо точечного diff.
* Склонен добавлять «удобные» зависимости (`pandas`) и использовать устаревшие
  API (plotly `show_link`), если не указать версии явно.
* Не знает про Python 3.14 по умолчанию — ограничения пришлось прописать в промпте.

**GitHub Copilot**

* Agent mode **генерирует код, но не проверяет запуск**: пропущенная миграция и
  падение на `no such table` обнаружились только при моём прогоне.
* Галлюцинирует версии библиотек и зависимости миграций (`$name`, отсутствующий
  `swappable_dependency`).
* Контекст обрезается на больших файлах: после добавления портфеля в `models.py`
  приходилось просить «покажи только изменённые методы».
* Free tier ограничен по числу запросов в месяц; в agent mode лимит расходуется
  быстрее, чем в обычном автодополнении.
* Нет памяти между чатами: ограничения «Python 3.14, без Docker, без Tinkoff»
  приходилось повторять в каждом новом диалоге.

**Общее для обоих:** ни один агент не гарантирует, что проект реально стартует;
проверка `check → makemigrations → migrate → test → runserver` остаётся на
разработчике.

### 7.2. Преимущества и недостатки

| | Преимущества | Недостатки |
| --- | --- | --- |
| **Claude 3.5 Sonnet** | Понимает смысл кода и бизнес-логику; сам находит скрытые дефекты (`nano`, `None` в тренде); аккуратно структурирует сервисы; пишет осмысленные тесты; объясняет решения | Медленный; дороже по времени; требует точных промптов и 3–4 итераций; иногда переусложняет и тянет лишние зависимости |
| **GitHub Copilot** | Мгновенная генерация; знакомый «человеческий» стиль; хорошо справляется с CRUD, формами, шаблонами; низкий порог входа; дешёвый старт | Не доводит до запускаемого состояния; ошибки в миграциях и финансах; дублирование логики; нужен постоянный контроль и ручное тестирование |

## 8. Выводы

1. **Claude 3.5 Sonnet** сильнее там, где нужно понять смысл кода и не сломать
   деньги: точность, транзакции, права доступа, обработка краевых случаев. Он
   сам нашёл дефект с `nano`, о котором я не просил прямо, и предложил
   архитектурно правильное решение (утилита + `DecimalField` + mock-фасад).
   Минусы — медленнее, требует более точных промптов и 3–4 итераций, иногда
   тянет лишние зависимости.

2. **GitHub Copilot** — инструмент быстрого прототипирования. Он моментально
   выдаёт работающий на вид CRUD, модели и шаблоны, но не проверяет, что проект
   реально запускается: пропущенные миграции и «продажа без уменьшения
   количества» — типичные примеры. Его сильная сторона — скорость и знакомый
   стиль кода, слабая — многошаговая логика и дисциплина миграций.

3. **Практическое правило.** Copilot — для каркаса, шаблонов, CRUD и быстрых
   правок «здесь и сейчас», с обязательным ручным ревью миграций и математики.
   Claude — для аудита, рефакторинга, финансовых расчётов, интеграций и всего,
   где ошибка стоит дорого. Идеальный процесс: Copilot генерирует черновик,
   Claude (или человек) проводит ревью и закрывает краевые случаи.

4. **Ограничения free-тарифов** сказались меньше, чем ожидалось: оба инструмента
   уложились в лимиты, но Copilot в agent mode быстрее упирается в контекст на
   больших файлах (`models.py` после добавления портфеля пришлось просить
   «покажи только изменённые методы»).
